# M04A — Reconstructed ad catalog and popularity retrieval

## Goal and scope

Build a deterministic, testable candidate-retrieval baseline using only the
**published TaobaoAd_x1 `train.csv`**. This is a **reconstructed observed-ad
catalog**, not a complete advertiser inventory. M04A does not claim online
retrieval quality, historical eligibility, temporal validity, or causal lift.

## Inputs and contracts

- Input: validated `train.csv` with the 21-column TaobaoAd_x1 schema.
- Identity: `adgroup_id` is the retrieval key; `customer` identifies its
  associated advertiser in this dataset, not a synthetic auction account.
- Metadata: `cate_id` and `brand` are copied from observed impressions.
  Conflicting metadata for one ad ID fails fast rather than silently overwriting.
- Score: **number of observed training impressions per ad**, not click-through
  rate, relevance, bid, or expected revenue. This avoids treating an unexposed
  item as a known negative and avoids popularity instability from rare clicks.
- Query: optional exact category/brand filters, explicit excluded ad IDs, and
  `k`. These filters are a **demo interface**, not verified production eligibility.
- Output: up to `k` distinct ad IDs ordered by descending impression count,
  then lexicographically ascending ad ID. Empty results are valid.

## Runbook

```bash
pytest
python -m sponsored_ads.retrieval_cli --limit 10000 --top-k 5
python -m sponsored_ads.retrieval_cli --top-k 5
```

Outputs are written under ignored `artifacts/m04a/`:
`catalog.json` (aggregated ad records) and `manifest.json` (provenance,
row counts, limitations). The full run streams rows but holds **one record per
unique ad** in memory; memory therefore scales with catalog cardinality.
For large catalogs, a disk-backed aggregation is a future optimization.

## Validation and acceptance

- Tests cover ordering/ties, filters, exclusion, empty result, invalid `k`,
  duplicate IDs, invalid counts, conflicting metadata, streaming aggregation,
  source split restriction, and JSON round-trip.
- A passing synthetic smoke test does **not** validate the full dataset.
- Complete M04A only after running the full catalog build and recording actual
  unique-ad count, duration, and any metadata conflicts.

## Evaluation boundaries

Observed impressions were selected by an unknown historical ad-serving policy.
The data lacks the complete eligible candidate set, request timestamps, bids,
and budgets. Therefore this baseline cannot establish true Recall@K against
all relevant ads, production eligibility, or point-in-time correctness.
`test.csv` is never read by this builder. Evaluation on observed clicks, if
added later, must be labeled as **historical-policy-biased diagnostic**.
