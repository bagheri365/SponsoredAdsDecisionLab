# M03A — Reproducible CTR development data

## Research objective

Prepare a reproducible, bounded-memory development sample from the **published training split** of `reczoo/TaobaoAd_x1`. The next patch (M03B) will compare static-feature and behavioral-feature CTR models. **No model is trained in M03A.**

## Source and scope

- Input: `data/TaobaoAd_x1/train.csv` (21 columns), validated by the Milestone 2 reader.
- The source has no event timestamp. Neither the published split nor our development split is verified chronological.
- The source includes `btag_his`, `cate_his`, `brand_his`, but their point-in-time construction is **not verified**.
- `test.csv` is not read. The development validation subset is for model selection; the published test split is reserved.

## Protocol

1. Stream and validate input rows using `taobao.iter_rows` (no whole-file pandas loading).
2. For each original **zero-based row index**, compute an eight-byte BLAKE2b hash from `seed:index:sample`. Include the row if the resulting uniform value is below `sample_rate` (default 5%). This is approximately uniform sampling, not a fixed-size sample and not class stratification.
3. Independently hash `seed:index:split`; assign sampled rows to validation with probability `validation_fraction` (default 20%).
4. Extract the static and behavioral features listed below; write two CSV files and a JSON manifest under `artifacts/m03a/` (git-ignored).
5. Preserve natural label prevalence in expectation. Do not rebalance or fit encoders on validation rows.

**Caveat:** The row-index split is reproducible but not user-disjoint, ad-disjoint, chronological, or guaranteed free of correlated duplicates. `--limit` selects the **first N source rows**, not a representative random sample. Use it for smoke tests only.

## Feature definitions

- Static categorical: `userid`, `cms_segid`, `cms_group_id`, `final_gender_code`, `age_level`, `pvalue_level`, `shopping_level`, `occupation`, `new_user_class_level`, `adgroup_id`, `cate_id`, `campaign_id`, `customer`, `brand`, `pid`, `btag`.
- Static numeric: `price` (must be finite and nonnegative).
- Behavioral: `history_length`; counts of candidate `cate_id`, `brand`, and `btag` in corresponding history arrays; whether the **last array element** matches candidate category or brand.
- Label: `clk` (binary).

IDs remain strings: numeric-looking IDs are **categorical identifiers**, not quantities. The `last_*` features refer to array position, not a verified event timestamp. Behavior sequences are used as supplied; no claims of causal or point-in-time correctness.

## Usage

```bash
pytest
python -m sponsored_ads.ctr_features_cli --limit 10000 --sample-rate 0.2
python -m sponsored_ads.ctr_features_cli --sample-rate 0.05
```

Outputs: `train_features.csv`, `validation_features.csv`, `sample_manifest.json`. Default sample is roughly 1.25 million rows across both splits; actual counts depend on deterministic sampling.

## Acceptance criteria

- Unit tests for feature definitions, missing history, invalid price, reproducibility, and split isolation pass.
- 10,000-row smoke run succeeds and manifest counts match output rows.
- Full train-only run completes on the user's machine; record actual counts and runtime in the milestone report.
- Do not mark this milestone complete based on unit tests alone.
