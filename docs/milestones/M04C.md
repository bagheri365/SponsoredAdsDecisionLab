# M04C — Held-out observed-click retrieval evaluation

**Status: protocol and evaluation core only; no Taobao evaluation has run.**

## Research question

Given a held-out *clicked impression*, does a training-catalog retriever include its observed ad in the top K? Compare popularity, category/brand affinity, and RRF fusion at K = 10, 50, 100 (with a fixed, declared retrieval pool). This is an **exposure-conditioned proxy**, not unbiased recall over eligible ads, an online CTR estimate, or causal lift.

## Data separation and validity gates

1. Construct the catalog **exclusively from published train.csv**. Do not use test.csv to create or enrich the catalog, popularity counts, postings, or hyperparameters. Record catalog hash, row counts, and provenance. The existing M04A catalog is train-derived but not point-in-time for each held-out request.
2. Evaluate on published **test.csv clicked impressions (`clk == 1`)**. Report the full clicked-row count, skipped malformed rows, and exact sampled subset if sampling is required. Stream the CSV; never load the 2.2 GiB file into a DataFrame. Do not tune on the final test set. If pool size or weights are tuned, create a separate train-only validation split first.
3. Published train/test split is **not verified temporal or user-disjoint**. Shopper histories lack timestamps and verified event ordering; `cate_his` / `brand_his` may contain future information relative to an impression. Before reporting results, audit leakage and history semantics as far as data permits. If unverifiable, label results exploratory and potentially contaminated.
4. The observed catalog is not an eligible-ad inventory. Missing test clicked ads are irretrievable; report **catalog coverage** and both unconditional and catalog-conditional metrics. Do not filter absent ads silently.
5. The test set contains *logged exposures*, not a counterfactual set of negatives. Do not use non-clicked impressions as evidence of irrelevance or report precision, true recall over relevant ads, unbiased offline policy value, or lift.

## Metric definitions

Unit of analysis: **clicked impression row**, not distinct user or distinct ad. Multiple clicked impressions from the same ad each count separately; disclose frequency concentration and optionally add ad-macro diagnostics later.

- `N_click`: number of valid held-out clicked impressions.
- `N_catalog`: clicked impressions whose ad ID appears in the training catalog.
- `catalog_coverage = N_catalog / N_click`.
- `hits_method@K`: number of clicked impressions where the observed ad appears in the method's first K unique IDs.
- `observed_click_recall@K = hits_method@K / N_click` (coverage-limited).
- `catalog_conditional_recall@K = hits_method@K / N_catalog` (only if denominator > 0; still exposure-conditioned).
- `fused_hit_sources`: for successful fused hits, categorize source metadata as affinity-only, popularity-only, both, or other. This is attribution of retrieval provenance, **not** incremental value or causal contribution.

Empty denominators are `null`, not zero. Require unique IDs in each ranking; a hit on an ad absent from the catalog is an evaluation-integrity error. Fix `pool_size`, tie-breaking, exclusions, and category/brand weights for every method comparison. No auction, bid, budget, or eligibility assumptions are introduced.

## Initial evaluation core

`src/sponsored_ads/retrieval_evaluation.py` defines `ClickCase`, `RetrievalObservation`, and `summarize_observed_clicks`. It is pure Python and has no data dependencies. Tests cover metric denominators, duplicate clicked impressions, missing-catalog ads, top-K, empty samples, malformed rankings, and fusion source attribution.
