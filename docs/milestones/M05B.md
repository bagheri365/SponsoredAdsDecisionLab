# M05B — Strict candidate pre-ranking bridge

**Status:** Implementation and synthetic tests; no real-data pre-ranking result yet.

## Scope

`candidate_preranking.py` accepts ordered `RetrievedAd` objects from M04B, a
`BehavioralIndex`, **explicitly supplied complete M03A feature rows keyed by adgroup_id**,
a compatible M05A LightGBM booster and its persisted contract. It returns a
bounded top-K ranked list with predicted CTR, original retrieval score and source
attribution, plus explicitly reported unscorable candidate IDs.

This is a **strict bridge**, not a complete online candidate feature assembler.
The M04A catalog lacks price, campaign_id, pid, user demographics, and many other
required model fields. The caller must supply these from a trusted, correctly
versioned feature source; this milestone does not create that source.

## Contract

- No fabricated defaults or refitting of categorical mappings.
- Missing or incomplete rows fail by default; `missing_policy='skip'` is opt-in
  and reports the skipped IDs in input order.
- Duplicate or unknown candidate IDs, mismatched adgroup IDs, contradictory
  category/brand values, invalid numeric inputs and invalid scores fail closed.
- M05A enforces ordered float32 encoding and unknown categorical value `-1`.
- Stable ranking: descending predicted CTR, ascending lexical `adgroup_id` on ties.
- `top_k=0` validates and scores any supplied rows but returns no ranked entries.

## Verification

```bash
pytest -q tests/test_candidate_preranking.py
pytest -q
```

Synthetic tests verify strictness, skip reporting, unknown categories, stable
tie-breaking, attribution and score checks. This does **not** validate latency,
request-time eligibility, CTR calibration for retrieved/unexposed candidates,
point-in-time history, or real-data ranking quality.
